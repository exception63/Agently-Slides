# 调研：AI 图表功能（学术报告常用）

> 2026-06-28。用户场景 = 经常做**学术报告**，要各种图表（柱/折线/散点/饼/雷达/箱线/桑基/网络/流程…），
> 希望 AI 按**数据或文字描述**生成图表插进 slides。**原则：不造轮子，用现成方案。**
> 本文给 A / B / C 三方案对比 + 推荐 + 落地点。**先调研，后写代码。**

## 0. 约束（Slidesmith DNA，决定一切取舍）

- **单文件**：一个 .html 自包含，能拷给别人直接开。
- **离线**：不依赖 CDN / 联网。
- **可移植 + 矢量优先**：换肤、缩放、导 PDF 都要清晰；图表最好跟着 deck 的设计令牌（`--accent` 等）走。
- **AI-first**：人不手搓图表，贴数据/写一句描述 → AI 出图 → 走现有「AI 待办」环回灌。
- **已有的最佳接入点**：`packages/studio/src/main.ts` 的「配图」流——`genQueue:{type, hint}` +
  分段开关 `#illSeg`（现「矢量 / 照片」）+ 规则块 `aiIllustrateSpec()` + 统一请求 `buildAllRequest()`
  + 图片库 `~/.slidesmith/library/<deck>/`。图表就是再加一类，几乎零新结构。

## 1. 环境探针（本机现状，决定哪些方案"今天能用"）

| 工具 | 有? | 用途 |
|---|---|---|
| matplotlib + pandas + numpy | ✅ | 方案 C 预渲染（箱线/小提琴/热力/密集散点…） |
| d3 (node) | ✅ | 方案 C 可选（要配 jsdom 才能出 SVG 字符串） |
| rsvg-convert | ✅ | SVG→PNG（截图/预览） |
| ECharts / Chart.js / Vega / Plotly / kaleido | ❌ | 方案 B 要新装重依赖 |

结论：**A 零依赖随时可用；C 今天就能用（matplotlib）；B 要引入重依赖且与 DNA 冲突。**

## 2. 三方案

### A — AI 直接画内联 SVG（同现在的「矢量配图」）
AI 读数据/描述 → 选图型 → **直接写一段 `<section>` 里的内联 `<svg>`**（坐标轴/刻度/图例/标签全手绘），
用 `var(--accent)` 等令牌着色。

- ✅ **零依赖、离线、单文件**——完美契合 DNA。
- ✅ **矢量**：换肤自动变色（用的是 CSS 令牌不是死 hex）、导 PDF 清晰、可后期手改（点哪改哪）。
- ✅ **体积极小**（实测一张约 1–2KB）。
- ✅ **复用现有环**：落进 `genQueue`，跟改字/配图同一个「一键发送」。
- ✅ **中文零障碍**（就是 HTML 文本）。
- ⚠️ **弱点**：极密集 / 需精确坐标算法的图（箱线、小提琴、热力图、桑基、上百点散点、对数轴+误差棒）
  手绘易出错、费 AI token。**结构化的柱/折线/饼/环/面积/雷达/中小散点没问题**（见实测 §3）。

### B — 内联运行时图表库（ECharts / Chart.js）
把库打进 deck，浏览器里实时渲染。

- ✅ 数据驱动、图型全、可交互。
- ❌ **破单文件**：ECharts min ≈ 1MB、Chart.js ≈ 200KB，**每个 deck 都背一份**。
- ❌ **Chart.js 是 canvas = 位图**：导 PDF 不清晰、违背"矢量优先"（ECharts 有 SVG 渲染器稍好）。
- ❌ 交互在投屏/PDF 里本就用不上（白背成本）。
- ❌ 本机没有，要新引依赖。
- 📌 **仅当将来真要"deck 里实时交互图表"才考虑**，现在不做。

### C — 预渲染成 SVG 再内联（authoring-time 用库，产物仍是静态 SVG）
出图时我（Claude Code）在本机跑 matplotlib / vega / d3 → 生成**主题化静态 SVG** → 内联进 deck。

- ✅ **数据驱动正确性**（库帮你算刻度/分位/布局）+ **产物仍是矢量 SVG**（零运行时依赖、离线、单文件）。
- ✅ 适合 A 搞不定的**复杂/密集/高精度**学术图。本机 matplotlib 今天就能用（实测 §3）。
- ⚠️ **中文要配 CJK 字体**（matplotlib 默认字体出□，见实测）——可修但是摩擦。
- ⚠️ **SVG 更重**（实测一张箱线 ≈ 34KB，是手绘的 ~20 倍：内嵌 DTD + 字形描边路径）。
- ⚠️ **颜色烧死成 hex**（不是 CSS 令牌）→ 换肤不跟着变；后期手改难。
- ⚠️ 多一道 authoring 流程（跑脚本）。

## 3. 实测（眼见为实）

- **方案 A** — 我手绘了 4 张学术图（分组柱 / 折线带标记 / 六维雷达 / 散点带趋势线），editorial 皮、
  令牌着色，一次成型、专业、零依赖：[`docs/screenshots/charts/demo-A-svg-direct.png`](screenshots/charts/demo-A-svg-direct.png)
- **方案 C** — matplotlib 出了一张箱线图（A 最难手搓的那类：四分位/须/离群点），主题色已注入、English 正常，
  **但中文标题成了□□□**（默认字体缺 CJK）：[`docs/screenshots/charts/demo-C-matplotlib.png`](screenshots/charts/demo-C-matplotlib.png)
  —— 一张图说清 C 的威力与代价。

## 4. 推荐：**混合，A 为默认 + C 作逃生舱，B 暂不做**

- **默认 = A（SVG 直出）**：覆盖 80% 学术图（柱/分组柱/堆叠柱/折线/面积/饼/环/雷达/中小散点/
  斜率图/误差棒小样）。复用「配图」环，几乎零新代码，最契合 DNA。
- **逃生舱 = C（matplotlib 预渲染→主题 SVG→内联）**：仅当数据**密集/复杂/要精确统计**（箱线/小提琴/
  热力/桑基/上百点散点/对数轴）时，AI 自行改走预渲染。规则里写明何时切换 + 中文字体要点。
- **B 搁置**：等真出现"deck 内实时交互图表"需求再说。

理由：A 与 C **产物都是内联 SVG**，对 deck 而言形态一致（单文件/离线/矢量），区别只是"谁画"——
简单的 AI 直接画，难的借 matplotlib 算。用户的核心诉求（贴数据/描述→出图→插页）两条都满足，
且都不破坏单文件离线。

## 5. 落地点（最小改动，全复用现有环）

1. **UI**：`#illSeg` 分段从 2 项（矢量/照片）扩到 3 项 —— **矢量 / 图表 / 照片**；
   `illType: 'vector'|'chart'|'photo'`。选「图表」时 hint 框提示改为
   "粘贴数据或描述，例：方法A 78%、方法B 88%…，要分组柱状图"。
2. **状态**：`genQueue` 的 `type` 加 `'chart'`（`{type:'vector'|'chart'|'photo', hint}`）。
3. **规则块**：新增 `aiChartSpec()`（与 `aiIllustrateSpec()` 并列）——
   读数据/描述→选对图型→画**干净内联 SVG**（坐标轴+刻度+图例+轴标题+单位，令牌着色，自包含，
   克制无 chartjunk）；附**逃生舱**：密集/复杂图可 matplotlib 预渲染成主题 SVG 内联（注明 CJK 字体）。
4. **组装**：`buildAllRequest()` 里 `anyChart` 时带上 `aiChartSpec()`（仿 `anyVec`）；
   `aiTaskBlock` 加一行图表指令。
5. **待办/图片库**：图表（SVG）跟矢量一样进待办、进图片库（可复用/管理）。
6. **AGENTS.md §4c**：加第 4 类 per-page 指令「配图 · 图表」，写清 A 默认 + C 逃生舱。
7. **验证**：`verify-ai-pane.mjs` 扩——分段有 3 项、图表指令进单一请求、图表规则块出现、图表项进图片库。

> 改动面 ≈ 在「矢量配图」旁复制一份"图表"类型 + 一个规则块 + AGENTS 一段 + verify 几条。
> 不引任何运行时依赖，不破单文件。
