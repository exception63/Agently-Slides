# Slidesmith 全面审查 · 2026-08-30

> 对象：`slidesmith` 插件（5 个 skill + 1 个命令 + MCP 桥）、浏览器 Studio、Mac 原生 app、手机/手表遥控、Slidesmith Live。
> 方法：读架构文档与交接稿；量化度量（体积 / 启动 / token 成本 / 仓库）；在浏览器里逐面板实际操作 44 页真实 deck；跑全部单元测试与类型检查。
> 目标：找出让它从「能用、好用」到「高级」之间还差的东西。按**影响 × 改动成本**排序，每条给证据和做法。

## 1. 效率

### 1.1 每个会话的「固定税」≈ 9k token，用户还没开口就交了 ★★★

| 来源 | 字节 | ≈ token |
|---|---|---|
| 5 个 skill 的 frontmatter（每会话全量载入） | 9.4 KB | ~3k |
| MCP 9 个工具的 schema + 描述（每会话全量载入） | 18 KB | ~6k |

`editorial-slides` 一条 description 就 3.3 KB——把 22 张皮的清单、动画分类、触发词全塞进了 description。

**做法**：description 只留「何时触发 + 一句话干什么」（≤ 400 字），清单和流程下沉到 SKILL.md 正文（只在被调用时读）；MCP 描述同理，把「怎么用」的长段落搬去 AGENTS.md，工具描述留一行。预计固定税降到 ~2k。

### 1.2 一次 AI 修改请求可能夹带 6 万 token 的 base64 ★★★

请求体是「修改要求 + **该页当前 HTML 原文**」。暂存盘的新图已经做了占位符（好），但**页面里已有的 base64 图没有剥**：

```
「研究一 · 设计」 181 KB · 其中 base64 图 181 KB   → 一次请求 ≈ 60k token
「研究二 · 设计」 126 KB · 其中 base64 图 125 KB
「虚实悖论」      114 KB · 其中 base64 图 113 KB
```

而且 AI 改完要把整段 `<section>` 原样回写，这笔账是**双倍**的。对一个「只想把标题改短点」的请求，99% 的 token 花在搬运图片上。

**做法**：发送前把 `src="data:image/…"` 换成 `src="sm-img://<id>"`（Studio 侧登记 id → base64 映射），回写时反向回填——和暂存盘的 `data-img-id` 是同一套机制，直接复用。

### 1.3 成品 5 MB，其中 3.9 MB 是没子集化的字体 ★★★

```
总 5.04 MB · 字体 3.93 MB（29 个 @font-face，全量）· 图片 0.65 MB · 脚本 0.28 MB · 讲稿 0.07 MB
```

一份 44 页学术 deck 的正文用字撑死两三千个，却嵌进了完整 CJK 字体。后果：文件大、在手机/iPad 副屏上打开慢、微信传不动、每次「另存为」都要写 5 MB。

**做法**：导出时按 deck 实际出现的字符做子集（`fonttools pyftsubset`，Python 已在用）。经验值 3.9 MB → 0.2–0.4 MB。顺手把「嵌入字体」**默认打开**（子集化之后不再有代价），彻底告别「墙内打不开」这件事——这是 6-29 那次黑屏事故的另一半，导出侧的 `nonBlockFonts` 至今是「可选 follow-up」。

### 1.4 冷启动：每次都现编译 TypeScript

MCP 服务与 CLI 用 `tsx` 直接跑源码，冷启动 **0.7 s**；`.mcp.json` 因此依赖 `node_modules/tsx`。**做法**：esbuild 预打包一份 `dist/cli.mjs`（构建脚本已在用 esbuild），MCP 启动 < 100 ms，也去掉对 `node_modules` 的运行时依赖。

### 1.5 仓库在自己长胖

`.git` 68 MB；`docs/screenshots/` **41 MB 被跟踪、回归脚本每次重写**（两份 PDF 就 22 MB），`studio/slidesmith-studio.html` 1.36 MB 构建产物也在 git 里、每次 build 一个新 blob。**做法**：截图只保留 contact-sheet 级别的几张，其余出 git（或 LFS）；构建产物由安装脚本现场生成。

## 2. 逻辑与架构

### 2.1 插件**装不到第二台电脑** ★★★

`plugin/slidesmith/.mcp.json` 里是硬编码的绝对路径：

```
/Users/zhouliying/.local/bin/node
/Users/zhouliying/同步空间/Claude Projects/SlidesHTML/presentsystems/node_modules/tsx/dist/cli.mjs
```

Mac app 同样绑死仓库（`RepoLocator` 找不到就报「找不到 presentsystems 仓库」），运行时还要 `node`、`python3`、`tsx`，装机要 `xcodegen`。**「高级插件」的底线是别人能装**。

**做法**（两步）：
1. 短期：`.mcp.json` 用 `${CLAUDE_PLUGIN_ROOT}`，配合 1.4 的预打包，插件目录自带一切；
2. 中期：app 内嵌 node 运行时 + 预编译桥，`.app` 独立可装（DMG），仓库只是开发用。

### 2.2 文档在三个地方打架 ★★

- **AGENTS.md** 说协作环「block on `slidesmith_wait`」；**active.md** 说「别用前台 wait 卡死对话，用后台 curl 自循环」。两份都是 AI 的必读，一份新会话读到哪份就照哪份做。
- **README / GUIDE / plugin README 停在 6-25**。之后两个月加的 Mac app、手机遥控、手表、Live 互动、元素批注、设计旋钮、搜图，人类文档里一个字没有；plugin README 只列 3 个 skill（少 phone-remote、live）。
- **交接稿里的「新玩法一行不用改中转」是错的**（服务端有消息类型白名单），这次已在 `new-block.md` 纠正，但交接稿原文还在。

**做法**：定一条规矩——AI 行为只以 AGENTS.md 为准，把 active.md 里「正解」搬进去删掉旧说法；README/GUIDE 按功能重写一遍（一次性半天）。

### 2.3 两套中转、一份协议、文件各拷一份 ★★

Cloudflare Worker（`workers.dev`）和自托管（`live.zhouliying.com`）协议相同，但：`ask.html` / `remote.html` 在两个目录**各一份 md5 相同的拷贝**；Studio 导出、iOS/Watch app 默认指 `workers.dev`，Live 指自托管；phone-remote SKILL.md 同时讲两套。任何一次改页面都要记得改两处，迟早分家。

**做法**：自托管为主（它已经证明国内更稳、还快 100 ms），Cloudflare 降为「可选部署目标」；两个目录共用一份 html（构建时复制），所有默认地址收成一个常量。

### 2.4 Studio 是一个 5,389 行的文件 ★★

`packages/studio/src/main.ts` 单文件 364 KB，最长函数 596 行，63 处 `innerHTML =`。功能还在快速加（两个月加了 8 个大块），每加一块都是在同一个文件里找位置。29 个回归脚本兜着，但：**没有统一入口**（`npm test` 只跑 40 个单元测试，不跑任何 `verify-*`），`verify-polish.mjs` 已坏未修，交接稿靠一句话提醒「那不是你弄坏的」。

**做法**：按现有的分节注释（`// ---- image tray`、`// ==== N3: Submit-to-AI` …）切成 10 个左右的模块，esbuild 本来就在打包，零运行时代价；加 `npm run verify` 串起全部回归；修或删 `verify-polish`。

### 2.5 两个「和 Claude 说话」的入口，心智模型没讲清 ★

Studio 网页的 **AI tab**（待办 → MCP 桥 → 握手的那个 Claude Code 会话）和 Mac app 的 **Claude 面板**（`claude-bridge.py` 起的独立进程）。用户在 app 里同时看到两者：待办发出去是给谁改？面板里那个 Claude 和握手的是不是同一个？代码里两者确实汇合到同一个桥，但界面上没有一句话告诉用户。**做法**：面板顶部一行状态「这个 Claude 就是 Studio 顶栏连着的那个 · 会话 X」，或干脆把待办发送键也放进面板。

### 2.6 四种运行时

Python（`build.py`、`smrelay.py`、`claude-bridge.py`）、Node/TS、Swift、Shell。对本人开发无妨；要做成别人能装的东西，每多一种运行时就多一类「我这台机器上没有」的支持问题。不必现在动，但 2.1 落地时要一起决定：桥用 Node 还是 Python，只留一个。

## 3. 人机交互

### 3.1 现场互动在 Studio 里**没有入口** ★★★

Live 是这两周最有价值的新能力，但它只存在于 skill 和 CLI 里：Studio 的「插入」面板没有「加一页扫码提问」，管理台是另一个网站、另一套视觉、另一次登录。用户要在 Claude 对话、Studio、管理台三个地方切换。

**做法**：Studio「插入」加一项「现场互动 · 扫码提问」——点了就走 `inject-live.mjs` 插页 + `smlive new` 建房间 + 把三个网址显示在右栏；再加一个「互动」小面板显示在线人数 / 已收提问数 / 一颗「关提问」。管理台仍留给事后看账。这一步做完，Live 才算是产品的一部分而不是旁边一个服务。

### 3.2 右栏 AI tab 一屏塞了四件事 ★★

首屏同时给出：整份 deck 的要求、本页要求、配图（矢量/图表/照片）、导入图片/搜图，外加 8 颗 `?`。对最常见的动作——「这一页改一下」——它只是四块中的一块。

**做法**：渐进披露。默认只显示一个大输入框「这一页想怎么改？」+ 发送；配图 / 导入 / 整份 deck 收成一行小按钮，点开才展开。`?` 合成一个「这个面板怎么用」。

### 3.3 同一件事两个地方做 ★

左栏「换装」（22 张卡片）和右栏「设计 → 皮肤」下拉都是换皮；「格式」的空状态写着「在预览中点选文字即可直接编辑」，下面却单摆一颗与选中无关的「插入图片」。**做法**：换皮只留「换装」，「设计」里的皮肤下拉改成只读的「当前皮肤」；「插入图片」归「插入」面板。

### 3.4 画布被两层工具栏夹着 ★

预览里 deck 自带的顶栏（`正大… 当前 段 0 · 1/44 ← → 全屏播放 演讲者 提词`）和 Studio 自己的顶栏叠在一起，1280 宽的屏上幻灯片只占约一半宽度。**做法**：编辑态隐藏 deck 自带顶栏，把「全屏播放 / 演讲者 / 提词」提到 Studio 顶栏；画布直接多出一截。

### 3.5 导出选项藏在 ⚙ 里，默认值还是「不安全」的那边 ★

「嵌入字体」「嵌入手机遥控」在一个齿轮弹层里，都默认关。不嵌字体 → 导出件在墙内可能打不开；不嵌遥控 → 现场想用手机翻页得回来重导。做完 1.3 之后两项都可以**默认开**，齿轮弹层就可以撤掉。

### 3.6 缺一个统一的「快捷入口」

所有动作靠面板和 `?` 找。高级工具的通行做法是 **⌘K 命令面板**：输入「换成学术」「导出 PDF」「加提词」「发给 AI」直接执行。它同时是搜索、帮助和快捷键表，对非技术用户比记菜单友好得多。

### 3.7 AI 改完只有 ✓，没有「改了什么」

页面从「已发送 · 等待」变成「✓ 已改」是好的反馈，但用户要靠眼睛对比才知道改了哪里。**做法**：`apply_patch` 带一句 `summary`，右栏显示「第 7 页：三个要点改为两栏，去掉了第二段铺垫」，配合已有的「还原本页」。

## 4. 成熟度：让它像一个产品

### 4.1 一键体检 `doctor` ★★★

这两个月里，「已装插件的缓存停在 6-25」这件事**两个月没人发现**，phone-remote 技能从来没被装上过；本周又出了「管理台显示开着、其实是关的」。这类「看起来正常、其实错位」的问题，靠人肉发现不了。

**做法**：一个 `smdoctor`（skill 或 CLI 一键）检查：插件缓存版本 vs 仓库版本 · 桥端口是否活着 · 中转 `/health` · 令牌是否通 · 认证边界六条 · 日志里最近的错误。输出一屏绿/红。Studio 顶栏的连接徽标点开也能跑同一份。

### 4.2 安装与发布

现在装一遍要：clone → `npm install` → `build:studio` → marketplace add → plugin install → `xcodegen` → 编译 app → 装到 `~/Applications`。版本号手改，插件级没有 CHANGELOG。**做法**：`scripts/release.mjs` 一条命令（打包 dist、bump 版本、写 CHANGELOG、`claude plugin update`）；app 出 DMG。

### 4.3 命名

`transcripts_html` 是唯一用下划线的 skill；`editorial-slides` 早已不只是「杂志风」，它是全部 22 张皮的出片器。改名会打断习惯，可以先在 description 里把「做任何风格的 slides」写在第一句。

### 4.4 秘密的存放

`~/.slidesmith/config.json` 明文存 Pexels / Google key；`~/.zshrc` 明文存 SMTP 密码和 Gamma key（此前已提醒）。至少 `chmod 600`，最好 Studio 里给一个「密钥」设置页，写进 Keychain。

## 5. 建议的推进顺序

**批次一 · 省钱省事（约 1–2 天）**
1. 字体子集化 + 嵌入字体默认开（1.3 / 3.5）
2. 已有 base64 图在请求里换占位符（1.2）
3. skill / MCP 描述瘦身（1.1）
4. 文档统一：AGENTS.md 一份真相 + README/GUIDE 补齐两个月功能（2.2）

**批次二 · 能装到别的机器（约 2–3 天）**
5. `${CLAUDE_PLUGIN_ROOT}` + esbuild 预打包（1.4 / 2.1）
6. `smdoctor` 一键体检（4.1）
7. 中转收成一份真相（2.3）
8. `npm run verify` 统一入口 + 修 verify-polish（2.4 的一半）

**批次三 · 产品感（约 3–5 天）**
9. Studio 里的「现场互动」入口 + 互动面板（3.1）
10. AI tab 渐进披露 + 换皮/插入归位 + 画布让位（3.2 / 3.3 / 3.4）
11. ⌘K 命令面板（3.6）· AI 回写带 summary（3.7）
12. main.ts 拆模块（2.4 的另一半，放在 UI 改造之后做，避免两头改）

**先不动的**：Mac app 内嵌运行时 / DMG（等批次二验证过路径解耦之后再定）；运行时收敛（跟 app 一起决定）；PPTX 导出（用户已说不做）。
