## 🔌 Studio ↔ Claude 协作机制（一图流）
1. `slidesmith_open(deckPath)` → 浏览器开 Studio + 握手（连上即顶栏「● 已连接 Claude」）。deck = **契约 HTML**（`#deck > .slide[data-id]`）。
2. **实时协作环（正解）= 后台 `curl /api/wait` 自循环脚本**（`run_in_background`，**别 nohup**否则 harness 跟不住）：只在用户真按「发送」时 exit→唤醒我，空闲在后台内部消化 ≈ 零 token。**新会话要重新挂一次**。别用前台 `slidesmith_wait`（卡死对话）。
3. 用户在 Studio 写「AI 待办」（改字 / 配图：矢量·图表·照片 / 导入图）→ 一键发送 → 我收到**单个 `.ai-tasks.md`** → 改写对应 `<section data-id>` → `slidesmith_apply_patch` 回灌。
4. **分工**：人做高频细活（点字/换色/字号/动画/移删元素，即时零 token）；AI 做模糊重活（经待办）。

- **【关键架构反转】桥的命从"拴在 Claude 会话上"改成"拴在 app 上"**。老形状是 MCP 进程自己 listen 8765，会话一关 Studio 失联。新增 `packages/bridge/src/remote.ts`：MCP 启动先探 8765，**有活着的桥就当 HTTP 客户端**（`BridgeFacade` 全异步窄口子，本地/远端各一实现），没有才自己起 → **终端老路完全不受影响**。不做这个的后果极隐蔽：`startBridge` 撞 EADDRINUSE 会**静默退到随机端口**，apply_patch 推进空桥 → 用户看到「AI 说改好了但屏幕没变」。CLI 加了 `mcp --attach-only`。
- **【新工具】`slidesmith_outline`**（`packages/bridge/src/outline.ts` + `/api/outline`）：列出当前 deck 的 页号·data-id·标题·版式，`withHtml` 可连整页 HTML 一起取。**存在理由**：`data-id` 是 Studio 导入时才生成的（`data-id → window.SLIDE_MAP[i] → s{i+1}`），磁盘文件里通常没有（editorial-slides 写的是 data-seg）→ 自由对话时 AI 读文件拿不到任何合法 id，apply_patch 必被拒。真机第一次跑就撞上了。服务端按**和 Studio 逐字相同**的规则复算（正则按 section 嵌套深度切，scope 到 `#deck`）。
- **【会静默毁工作的洞·已堵】读页之前必须先向 Studio 要一次最新 deck**：桥里 `deck.html` 只在 导入/AI补丁后/用户按保存 时刷新，**手打的字不在其列** → 用户手改两页后让 AI 改第 5 页，AI 读到手改前的版本、回写 → 手改被无声抹掉。修法：`/api/outline` 先广播 `{type:'sync-request'}`、等 Studio 回 `exported`（1.5s 超时），main.ts 加一行响应。返回带 `synced` 标志。**改了 main.ts，已 `node scripts/build-studio.mjs` 重建。**
